# بستهٔ سورس ترب‌چت — دستیار خرید حضوری

این بسته برای انتقال سورس و آماده‌سازی انتشار است. ساخت آن هیچ استقرار، تماس، پیامک یا درخواست سرویس خارجی انجام نمی‌دهد. دیتابیس، دیتاست و تنظیمات خصوصی باید جداگانه و با دسترسی مناسب در محیط مقصد آماده شوند.

## ساخت و بررسی

نیازمندی: Python 3.10 یا جدیدتر؛ اسکریپت فقط از کتابخانهٔ استاندارد استفاده می‌کند. دستورها را در ریشهٔ پروژه اجرا کنید:

```bash
python3 scripts/package-release.py --check
npm run release:optimized
npm run release:boxapi
python3 -m zipfile -t releases/torobchat-boxapi-source.zip
```

دستور اول فقط فایل‌های مجاز را اسکن می‌کند و فایل خروجی نمی‌سازد. دو دستور بعدی خروجی‌های optimized و boxapi را با EDITION.md و نمونه تنظیمات مناسب می‌سازند. دستور BoxAPI فایل `releases/torobchat-boxapi-source.zip` را می‌سازد، تمام ورودی‌های ZIP را با `testzip()` و هش‌های manifest بررسی می‌کند و SHA-256 خود ZIP را چاپ می‌کند. فایل موجود بازنویسی نمی‌شود؛ برای نسخهٔ تازه نام جدید انتخاب کنید:

```bash
python3 scripts/package-release.py --output releases/torobchat-boxapi-source-v2.zip
```

`--root /absolute/project/path` برای ریشهٔ صریح یا fixture تست قابل استفاده است. مسیر نسبی خروجی نسبت به همین ریشه تفسیر می‌شود. خروجی باید پسوند `.zip` داشته باشد و زیر `ROOT/releases/` باشد؛ مسیر بیرون آن، symlink و بازنویسی فایل موجود رد می‌شود. هنگام بسته‌بندی فایل‌ها را تغییر ندهید.

## محتوا و مرزها

Allowlist شامل فایل‌های اصلی پروژه، lockfile، تنظیمات ساخت و استقرار، Dockerfile، `.env.example`، سورس، تست، migration، اسکریپت، مستندات و مجوز فونت‌ها است. فقط پسوندهای متنی شناخته‌شده و فونت‌های دارای امضای مورد انتظار از پوشه‌های مجاز پذیرفته می‌شوند. تصاویر برداری SVG متنی قابل بسته‌بندی‌اند. فقط سه آیکون مورد استفاده در مسیرهای دقیق `public/brand/torob-radish.gif`، `public/brand/torob-rotate.gif` و `public/brand/torob-radish.png` با بررسی امضای GIF/PNG و اسکن الگوهای credential پذیرفته می‌شوند؛ منشأ در `public/brand/README.md` آمده است. باینری‌های دیگر از جمله عکس، ویدئو و آرشیو خودکار وارد بسته نمی‌شوند. فایل لازم جدید باید آگاهانه به allowlist اضافه و تست شود.

موارد زیر وارد بسته نمی‌شوند و محتویات تنظیمات خصوصی نیز برای اسکن باز نمی‌شود:

- تمام `.env*` به جز `.env.example` در ریشه، credential و secret fileهای شناخته‌شده؛
- `archive/` و بک‌اند قدیمی (خارج از allowlist)؛
- `data/`، دیتاست ZIP/CSV و دیتابیس محلی یا dump؛
- `node_modules/`، `.next/`، `.git/`، cache، build، dist، coverage و خروجی release؛
- log، گزارش Playwright، snapshot مرورگر، reference/capture و screenshot؛
- فایل‌های پنهان غیرمجاز و باینری یا پسوند ناشناخته.

Symlink در درخت سورس مجاز رد می‌شود و دنبال نمی‌شود. پوشه‌های مستثنا پیش از خواندن کنار گذاشته می‌شوند. `.env.local` برای استفادهٔ محلی دست‌نخورده باقی می‌ماند.

## اسکن اسرار و manifest

متن همهٔ فایل‌های انتخاب‌شده بررسی می‌شود: کلیدهای شناخته‌شدهٔ سرویس‌ها، private key، Bearer token، URL دارای نام‌کاربری/رمز و مقدارهای مشکوک اختصاص‌یافته به فیلدهای credential. بدنهٔ فونت‌ها و سه آیکون مجاز نیز برای الگوهای token بررسی می‌شود. فایل JSON با شکل رجیستری مخاطبان تأییدشده نیز رد می‌شود؛ رجیستری باید بیرون کل پوشهٔ پروژه باشد. متن نامعتبر UTF-8 یا باینری با پسوند سورس، خطا ایجاد می‌کند. خطا فقط مسیر و شمارهٔ خط را نشان می‌دهد و مقدار حساس را چاپ نمی‌کند. اسکن الگومحور است؛ کلیدهای obfuscated یا قالب‌های ناشناخته نیاز به بازبینی انسانی دارند.

فیلدهای credential و `DATABASE_URL` در `.env.example` باید خالی باشند. اطلاعات واقعی را فقط در متغیرهای خصوصی محیط مقصد وارد کنید. placeholder مستند و مقدار کوتاه تست به‌عنوان کلید واقعی معرفی نمی‌شود؛ آزمون‌های مربوط به secret باید مقدار fixture را هنگام اجرا بسازند تا خود تست حاوی token کامل قابل انتشار نباشد.

در `RELEASE-MANIFEST.json` داخل ZIP، مسیر، طول بایت و SHA-256 هر فایل ثبت می‌شود. خود manifest در فهرست خودش نیست. ترتیب فایل، زمان ZIP و permission ثابت‌اند؛ با ورودی و نسخهٔ Python/zlib یکسان، خروجی قابل تکرار است. فایل ZIP فقط پس از موفقیت تمام بررسی‌ها با انتشار atomic بدون بازنویسی در مسیر نهایی قرار می‌گیرد.

## آزمون و استفاده در مقصد

```bash
npm test -- tests/release.test.ts
```

تست‌ها fixture موقت می‌سازند و include/exclude، عدم افشای مقدار حساس، symlink، مسیر خروجی، عدم بازنویسی، manifest، یکسانی بایت ZIP و بررسی CRC را با اجرای واقعی Python بررسی می‌کنند. برای انتخاب Python دیگر، متغیر `PYTHON` را تنظیم کنید.

در مقصد، پس از استخراج در پوشهٔ خالی، راهنمای [استقرار](deploy-liara.md)، [Neshan](neshan.md) و [درگاه استعلام](contact-gateway.md) را دنبال کنید: متغیرهای خصوصی سرور، دیتابیس پایدار، migration/import دیتاست جداگانه، worker و HTTPS callback باید طبق نیاز آماده شوند. حالت تماس واقعی نیازمند تنظیمات و تأییدهای مستقل است. بسته دارای دیتاست یا کلید نیست؛ داشتن ZIP به معنی آماده‌بودن دیتابیس یا انجام استقرار نیست.
