# بازیابی معنایی پیش از LLM

خواسته کاربر: امبدینگ OpenAI small یا large از BoxAPI پیش از پاسخ LLM، مرتبط کردن نیاز کاربر با دیتاست واقعی، ساخت کامل و راهنمای اتصال. انتخاب framework را صریحاً به مهندس واگذار کرده است؛ این سند تصمیم اجرایی مهندس است، نه ادعای تأیید جزئیات توسط کاربر.

## رویکردها
- تعویض runtime موجود با LangGraph: حالت و ابزارها را تکرار می‌کند و مشکل بازیابی را به‌تنهایی حل نمی‌کند.
- RAG مستقل با framework تازه و دیتابیس جدا: هزینه نگهداری و همگام‌سازی بیشتر.
- انتخاب اجرایی: workflow تایپ‌شده موجود + لایه embedding/retrieval مستقل و pgvector در همان PostgreSQL/PGlite؛ جست‌وجوی ترکیبی متنی و برداری. ماژول‌ها مرز مشخص دارند و بعداً می‌توان آن‌ها را به LangGraph منتقل کرد.

## قرارداد
`message → local constraints → query embedding → hybrid retrieval → same-offer eligibility → LLM tools → validated UI`.
امبدینگ قصد/بودجه را به ساختار JSON تبدیل نمی‌کند؛ بردار برای شباهت معنایی است. قیدها و شناسه‌های صریح مستقل‌اند. محصول بازیابی‌شده انتخاب قطعی کاربر نیست. شماره‌ها، مختصات شخصی و اطلاعات حساب در اسناد embedding وارد نمی‌شوند. فقط عنوان/برند/مدل/دسته/مشخصات واقعی کالا ایندکس می‌شوند؛ قیمت و موجودی در متن برداری ذخیره نمی‌شوند.

BoxAPI طبق مستندات فرستاده‌شده کاربر: `https://ai.boxapi.ir/ai/v1/embeddings`، مدل پیش‌فرض `text-embedding-3-small` با ۱۵۳۶ بعد. large قابل تنظیم؛ مدل/بعد/provider/version از هم جدا، تغییر آن‌ها نیازمند ایندکس جدید است. LLM فعلی 9router مستقل می‌ماند. هیچ کلیدی از LLM به embedding به‌طور ضمنی ارث نمی‌رسد.

ایندکس محصولات batch، قابل ادامه و بر پایه hash سند، با dry-run پیش‌فرض و اجرای واقعی فقط با گزینه صریح است. namespace مجزا برای هر فضای برداری. query embedding در حافظه کوتاه cache می‌شود، نه پیام خام در DB. quota اتمی درخواست و سقف واحد ورودی محافظه‌کارانه، timeout و بدون retry خودکار. هیچ ingestion یا تماس پولی خودکار در build/start/status وجود ندارد.

جست‌وجوی full-text فعلی + pgvector cosine با RRF. شناسه/اسناد متفاوت با هم مخلوط نمی‌شوند؛ hard filters با همان offer واقعی کنترل می‌شوند. نتیجه شباهت، تأیید موجودی/تناسب کامل نیست. نبود کلید/ایندکس/شبکه، fallback متنی صریح دارد؛ بدون وانمود کردن به semantic فعال.

## مرز تأیید و تست
مستندات رسمی OpenAI و pgvector بررسی می‌شوند. تست‌های فنی جدید با DB موقت و fetch جعلی، بدون اعتبار واقعی، بررسی type/lint/build. درخواست قبلی کاربر برای عدم تکرار سناریوها: E2E و chat completion واقعی اجرا نمی‌شوند. ایندکس انبوه ۲۲۵۹۰۳ کالا روی اعتبار محدود هکاتون بدون بررسی هزینه و تأیید صریح اجرا نمی‌شود. مسیر فایل کلید هنوز لازم است؛ ساخت مستقل از آن پیش می‌رود.
