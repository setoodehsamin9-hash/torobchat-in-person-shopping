# اتصال امبدینگ BoxAPI به ترب‌چت حضوری

این نسخه لایه RAG واقعی دارد، اما فعال شدن بازیابی معنایی نیازمند **کلید و بردارهای ساخته‌شده** است. نصب کد یا وارد کردن کلید به‌تنهایی به معنی آماده بودن ایندکس تمام محصولات نیست. مسیر `/settings` پوشش واقعی و وضعیت را نشان می‌دهد. طبق درخواست جدید، چت نیز به BoxAPI با `gpt-6-luna` منتقل شده است. امبدینگ مستقل از مدل چت و با `text-embedding-3-small` است؛ مدل چت نمی‌تواند جای مدل بردارساز قرار بگیرد.

## وارد کردن کلید

۱. در پنل هکاتون BoxAPI، اعتبار را با حساب خودتان فعال کنید و API Key را کپی کنید. این مرحله، رمز حساب یا کلید نباید در گفتگو ارسال شود.

۲. در فایل `.env.local` ریشه همین پروژه، مقدار خالی زیر را پر کنید. محل متغیرها آماده شده است:

```dotenv
EMBEDDING_ENABLED=true
EMBEDDING_BASE_URL=https://ai.boxapi.ir/ai/v1
EMBEDDING_API_KEY=کلیدی_که_از_BoxAPI_گرفتی
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSIONS=1536
EMBEDDING_DAILY_REQUEST_LIMIT=100
EMBEDDING_DAILY_INPUT_LIMIT=200000
EMBEDDING_TIMEOUT_MS=8000
```

آدرس و مدل‌های پشتیبانی‌شده از مستندات هکاتون ارسالی کاربر گرفته شده‌اند؛ اعتبار حساب، نرخ BoxAPI و پاسخ زنده آن در این مرحله آزمایش نشده‌اند. کلید در سرور می‌ماند و در تنظیم فعلی همان حساب BoxAPI برای چت و امبدینگ استفاده می‌شود و هیچ متغیر `NEXT_PUBLIC_` برای آن وجود ندارد. اگر کلید قبلاً در یک فایل ذخیره شده، فقط مسیر فایل را بدهید، نه محتوایش را در گفتگو.

## ساخت ایندکس با کنترل مصرف

**PGlite محلی باید یک مالک داشته باشد:** برای اجرای CLI، ابتدا سرور برنامه را در ترمینال آن با Ctrl+C متوقف کنید. روی PostgreSQL واقعی این محدودیت فایل محلی وجود ندارد. Node 22 یا جدیدتر لازم است.

بررسی بدون مصرف API (پیش‌فرض):

```bash
npm run embeddings:index -- --limit=100
```

این دستور جدول‌های لازم را در دیتابیس آماده می‌کند و تعداد اسناد نیازمند بردار را می‌شمارد؛ هیچ امبدینگی نمی‌سازد. `input_units` تعداد بایت UTF-8 است، نه قیمت یا توکن دقیق. عبارت `embedded` در خروجی dry-run یعنی اسناد در انتظار ساخت، نه بردارهای واقعاً ساخته‌شده.

فقط بعد از بررسی اعتبار و تصمیم شما، ساخت محدود **واقعاً مصرف‌کننده API**:

```bash
npm run embeddings:index -- --execute --limit=16 --batch-size=16 --max-requests=1
```

برای نمونه نمایشی بهتر می‌توانید یک دسته واقعی از دیتاست را محدود کنید؛ نام دسته باید دقیقاً با مقدار دیتابیس یکسان باشد. یک نمونه ۱۶تایی به معنی پوشش همه دیتاست نیست. ساخت مجدد همین دستور از checkpoint همان فضای برداری/دسته ادامه می‌یابد؛ اسناد ساخته‌شده با hash یکسان دوباره هزینه ندارند. با تغییر مشخصات سند، در چرخه کامل بعدی بردار تازه لازم است. هر اجرا سقف تعداد درخواست خود را دارد و در خطا خودکار تکرار نمی‌شود. برای کل دیتاست، ابتدا dry-run بزرگ‌تر و نرخ واقعی BoxAPI را بررسی و سقف روزانه را آگاهانه تغییر دهید؛ محدودیت محافظه‌کارانه فعلی برای ساخت کامل ۲۲۵۹۰۳ محصول در یک روز کافی نیست.

ساخت HNSW بعد از بارگیری بردارها، بدون تماس با مدل:

```bash
npm run embeddings:index -- --create-index
```

سپس نسخه تازه را بسازید و اجرا کنید:

```bash
npm run build
bash START_LOCAL.sh
```

بدون HNSW هم جست‌وجوی دقیق pgvector کار می‌کند، ولی برای ایندکس بزرگ کندتر خواهد بود. PostgreSQL مقصد باید افزونه `vector` و مجوز ایجاد آن را داشته باشد. PGlite این پروژه از افزونه همراه نسخه نصب‌شده استفاده می‌کند. محدودیت حافظه/فضا و زمان ایجاد ایندکس روی کل دیتاست در این مرحله سنجیده نشده‌اند.

## مدل Small یا Large

پیش‌فرض Small است؛ Large هم پشتیبانی می‌شود:

```dotenv
EMBEDDING_MODEL=text-embedding-3-large
EMBEDDING_DIMENSIONS=3072
```

ابعاد پیش‌فرض Small برابر ۱۵۳۶ و Large برابر ۳۰۷۲ است. API مدل‌های نسل سوم پارامتر dimensions دارد؛ می‌توانید Large را مثلاً با ۱۵۳۶ بعد تنظیم کنید. کیفیت واقعی فارسی باید با پرسش‌های پروژه ارزیابی شود، نه صرف نام مدل. [راهنمای رسمی OpenAI](https://developers.openai.com/api/docs/guides/embeddings)

هر ترکیب endpoint، مدل، ابعاد و نسخه سند namespace جدا دارد. تغییر هرکدام یعنی ایندکس قدیمی برای پرسش جدید استفاده نمی‌شود. برای ۳۰۷۲ بعد، ایندکس HNSW از halfvec استفاده می‌کند و نامزدها با بردار اصلی مجدداً مرتب می‌شوند. [مستندات رسمی pgvector](https://github.com/pgvector/pgvector)

## جریان پردازش

1. وضعیت گفتگو و محدودیت‌های روشن پیام خوانده می‌شوند؛ امبدینگ بودجه یا قصد را به JSON تبدیل نمی‌کند.
2. پیام به بردار تبدیل می‌شود و به همراه جست‌وجوی متنی در عنوان/مدل، نامزدهای واقعی را پیدا می‌کند. امتیازها با RRF ترکیب می‌شوند.
3. اگر بودجه، اقساط یا مکان انتخاب شده، یک offer واقعی باید همه شرط‌ها را هم‌زمان داشته باشد. تشابه دسته فروشگاه، سند فروش کالا نیست.
4. LLM، نتایج تایپ‌شده را می‌بیند و ابزار لازم را انتخاب می‌کند؛ محصول بازیابی‌شده خودبه‌خود به انتخاب قطعی کاربر تبدیل نمی‌شود.
5. قیمت، مشخصات، ساعت و اقساط از دیتابیس دوباره خوانده می‌شوند. رابط از بلوک معتبر ساخته می‌شود؛ متن آزاد مدل برای ادعای بی‌پشتوانه نمایش داده نمی‌شود.

Runtime اختصاصی موجود با مراحل مشخص گسترش داده شده؛ LangChain یا LangGraph نصب نشده‌اند. این انتخاب برای نگه‌داشتن کنترل‌های فعلی داده و حذف یک لایه تکراری است و انتخاب مهندس بوده است.

## صرفه‌جویی و شکست امن

- هر محصول یک سند کوتاه از عنوان، برند، مدل، دسته و حداکثر ۱۲ مشخصه دارد؛ قیمت، موجودی، شماره و آدرس در اسناد ایندکس نیستند.
- query cache حافظه‌ای پنج‌دقیقه‌ای و سقف دو درخواست امبدینگ تازه در هر نوبت گفتگو وجود دارد. ابزار جست‌وجو نیز می‌تواند یکی از این دو درخواست را برای پرسش دقیق‌تر مصرف کند.
- سقف روزانه درخواست و ورودی به‌طور اتمی در DB رزرو می‌شود. درخواست ناموفق هم ممکن است یک رزرو مصرف کند؛ توقف سرور آن را پاک نمی‌کند.
- بایت UTF-8 به‌عنوان سقف محافظه‌کارانه ورودی شمرده می‌شود؛ توکن خروجی امبدینگ نداریم. توکن گزارش‌شده از API جدا ذخیره می‌شود. هیچ سقف محلی تضمین مبلغ نهایی BoxAPI نیست.
- ایندکس خالی هیچ درخواست query embedding نمی‌فرستد. کلید غایب، افزونه غایب، قطع شبکه، رد کلید یا سقف مصرف به جست‌وجوی متنی با وضعیت صریح برمی‌گردد.
- متن خام گفتگو در جدول امبدینگ ذخیره نمی‌شود. مختصات GPS نشست به سرویس embedding ارسال نمی‌شود؛ شماره‌ها و جفت‌مختصات رایج در متن پرسش نیز حذف می‌شوند. پیام حساس را وارد گفتگو نکنید.

این مرحله با تست فنی آفلاین و DB موقت بررسی شده؛ بدون کلید/اجازه ساخت ایندکس، هیچ موفقیت واقعی BoxAPI یا بازیابی معنایی از کل دیتاست ادعا نمی‌شود.


## نتیجه بررسی این نسخه

در ۲۳ اکتبر ۲۰۲۶، dry-run کل ۲۲۵۹۰۳ محصول واقعی را خواند: ۶۴۵۷۳۶۰۷ بایت متن UTF-8 و صفر درخواست API. این حجم، شمار دقیق توکن یا هزینه نیست. بردارهای خام Small با ۱۵۳۶ بعد برای این تعداد، حدود ۱٫۳۹ گیگابایت فضای اعداد نیاز دارند؛ سربار ردیف و HNSW جداست. ساخت بردارها روی اعتبار محدود هکاتون هنوز اجرا نشده است. ۴۸ تست فنی آفلاین و build/typecheck/lint موفق شدند. endpoint وضعیت پس از اجرا، ذخیره‌ساز آماده و صفر محصول ایندکس‌شده را نشان داد؛ کلید غایب بود.
